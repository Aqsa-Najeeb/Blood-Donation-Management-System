======================================================================
1. OVERVIEW
======================================================================
Life Link is a full-stack web application built from the Figma design
(INTROTOSE-UI-UX) for donor discovery, controlled blood request dispatch
(maximum 3 concurrent donor alerts), fulfillment pipeline tracking,
donor/recipient workspaces, private in-app coordination, and user governance.

3. IMPLEMENTED ARCHITECTURAL LAYERS
======================================================================
1) Database & ORM Layer (prisma/schema.prisma, prisma/seed.js, backend/prisma.js)
   - MySQL schema with 9 models and relational integrity:
     users, donation_milestones, blood_requests, request_invitations,
     chat_threads, chat_messages, notifications, safety_reports,
     newsletter_subscribers
   - Seed script (prisma/seed.js) for initial donors, recipient, requests,
     invitations, milestones, chat thread/messages, and notifications
   - Singleton PrismaClient wrapper in backend/prisma.js

2) Express REST API & Auth Middleware Layer (backend/)
   - backend/app.js: Express app wiring CORS, JSON body parsing, /api/health,
     REST route modules, /api 404 handler, static serving for src/, and global
     error middleware
   - backend/middleware/auth.js: signToken, requireAuth, optionalAuth (JWT)
   - backend/utils/serializers.js: sanitizeUser (strips passwordHash, masks
     phone/CNIC in public listings), serializeRequest
   - REST Route Modules:
     - backend/routes/auth.js: /api/auth/register, /api/auth/login, /api/auth/me
     - backend/routes/donors.js: /api/donors/availability, /api/donors, /api/donors/:id
     - backend/routes/requests.js: /api/requests, /api/requests/:idOrCode,
       POST /api/requests, POST /api/requests/:idOrCode/invite (3-donor cap),
       PATCH /api/requests/:idOrCode/stage, POST /api/requests/:idOrCode/reactivate/:donorId,
       POST /api/requests/:idOrCode/cancel, POST /api/requests/:idOrCode/rate
     - backend/routes/donorActions.js: /api/donor/alerts,
       /api/donor/alerts/:invitationId/accept, /decline, /advance
     - backend/routes/chats.js: /api/chats, POST /api/chats,
       POST /api/chats/:threadId/messages, PATCH /api/chats/:threadId/archive
     - backend/routes/settings.js: /api/settings, /api/settings/freshness,
       /api/settings/password, DELETE /api/settings/account,
       /api/notifications, /api/notifications/read, /api/reports (3-report
       auto-restriction), /api/newsletter

3) Frontend State, Routing & API Sync Layer (src/js/store.js, src/js/main.js)
   - Hash-based client router supporting 14 screens:
     "/", "/find-donors", "/request-blood", "/donor-dashboard",
     "/recipient-dashboard", "/donor-profile", "/request-track", "/chat",
     "/how-it-works", "/about", "/safety-faqs", "/privacy-settings",
     "/login", "/signup"
   - Probes /api/health on startup; hydrates and syncs via fetch('/api/...')
     with JWT Bearer auth when MySQL is connected, with localStorage fallback
     when MySQL is offline

4) Presentation / UI Component Layer
   - Shared UI (src/js/components.js): Header, Footer, LahoreMapPreview,
     ToastBanner, GlobalModal
   - Public Pages (src/js/pages-public.js): HomePage, AboutPage,

   - Matching & Tracking Pages (src/js/pages-matching.js): FindDonorsPage,
     CreateRequestPage, RequestTrackPage
   - Workspace & Profile Pages (src/js/pages-dashboards.js): DonorDashboardPage,
     RecipientDashboardPage, DonorProfilePage
   - Messaging, Settings & Auth Pages (src/js/pages-account.js): ChatPage,
     PrivacySettingsPage, LoginPage, SignupPage

5) Entry & Styling Layer (src/index.html, src/find-donors.html, src/input.css, src/output.css)
